# Exams and Results Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monthly / mid-term / final exams with papers per class and subject, marks entry by the subject teacher, live results until publish (snapshot on publish), annual weighted results, and printable exam and annual report cards.

**Architecture:**
- **Data:** `GradeScale`, `GradeBand`, `ResultScheme`, `Exam`, `ExamPaper` are `ICampusOwnable` (Main Campus rows apply everywhere); `PaperSection`, `Mark`, `SectionResult`, `StudentResult`, `ResultRemark` are `ICampusScoped`. One migration.
- **One calculator:** `ResultCalculator` (pure, no I/O) turns papers + marks + grade bands into subject results, overall result and positions; both live tabulation and the publish snapshot use it. `AnnualCalculator` (pure) combines per-type percentages with scheme weights.
- **Access** in one place: `ExamAccess` (admin path, subject-teacher path, class-teacher / subject visibility).
- **UI:** an Exams menu group with Exams, Marks entry, Results, Grading pages, a print page for cards, and a student Results tab.

**Tech Stack:** .NET 10, ASP.NET Core, EF Core 10 (SQL Server), React 19, TypeScript, Tailwind v4, lucide-react, Python 3 e2e scripts (stdlib).

**Spec:** `docs/superpowers/specs/2026-11-11-exams-design.md`

## Global Constraints

- **Git:** work on `main`. **No new branch, no commits.** Leave changes uncommitted.
- **Migration:** one migration `Exams`; regenerate (remove + add) if a later task changes the schema. Filtered index filters must not use `NOT IN`; run `sqlcmd` with `-I`.
- **Wording:** user-visible text says "Main Campus", never "HQ".
- **Numbers:** marks `decimal(6,2)`; percentages rounded to 2 dp (`MidpointRounding.AwayFromZero`); positions use competition ranking (1, 2, 2, 4) among passed students only.
- **Defaults:** papers 100 / 33 (Monthly 25 / 9); grade scale A+ 90, A 80, B 70, C 60, D 50, E 40, F 0 (IsFail); scheme Monthly 20, MidTerm 30, Final 50, Other 0, MustPassFinal true.
- **Admin path:** module Edit (`marks:Edit` / `results:Edit` / `exams:Edit`) **and** (`sections:Edit` or `staff:Edit`).
- **Teacher path:** caller's staff (linked login, not left) holds a current teaching assignment for (section, subject) of the paper.
- **Error copy (exact):**
  - "Marks can be entered only while the exam is open."
  - "This result is published. Unpublish it first."
  - "Only the subject teacher or an admin can enter these marks."
  - "Submitted. Ask an admin to return it."
  - "Weights must add up to 100."
- **E2E:** new `tests/e2e/exams_e2e.py`; reuse `sms_client`, `academics_e2e`, `students_e2e` (`admit`), `onboarding_e2e` (`make_staff`, `assign`, `login_body`, `retire_staff`), `attendance_e2e` (`qa_section`, `admit_on`, `teacher_with_login`, `save`, `working_days_back`). Add cleanup kind `exams` (deleted before `holidays`). An exam can be deleted only while it has no marks, so groups that enter marks unpublish and close their exams (all named `QA …`); the final task soft-deletes leftover QA exams through SQL, after asking the user.
- **Regression:** after each API task run `attendance_e2e.py marking reports`, `onboarding_e2e.py assignments`, `students_e2e.py role-access`; add `"exams-menu"` before `"settings"` in every menu assertion (academics, students, hiring, attendance) in Task 1.

## Review Focus

1. **Student moved between sections mid-term:** marks are stored with the section the student sat in; the tabulation for a section lists only marks taken in that section, and publishing one section never snapshots another section's marks. Test: Task 3 `marks_follow_section`.
2. **Grade scale or scheme changed after publish:** a published exam's cards keep the old grade / % (snapshot), live sections use the new scale. Test: Task 4 `snapshot_survives_scale_change`.
3. **Paper total lowered below entered marks:** refused (400) while marks above the new total exist. Test: Task 2 `total_below_entered_marks_refused`.
4. **Teacher whose assignment ended:** cannot save or submit that paper any more; admin can. Test: Task 3 `ended_assignment_blocks_teacher`.
5. **All subjects exempted / nothing entered:** the student shows "Not entered" (no %, no grade, no position) and never divides by zero. Test: Task 4 `nothing_entered_no_crash`.
