# Fees Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fee heads and class-wise structure (Main Campus default, campus override), concessions, monthly challans with arrears carry-forward and late fine, counter/bank payment collection with receipts, defaulters, reports and a student Fees tab.

**Architecture:**
- **Data:** `FeeHead`, `FeeStructure`, `FeeSettings` are `ICampusOwnable` (Main Campus rows apply everywhere, campus rows override); `StudentConcession`, `FeeVoucher`, `FeePayment` are `ICampusScoped`; `FeeVoucherLine` belongs to its voucher. One migration `Fees`.
- **One calculator:** `FeeCalculator` (pure, no I/O) turns resolved charges + concession candidates + sibling position + settings into voucher lines; preview, generate and single-voucher all use it. Voucher state changes (carry, cancel, pay, void) live in one service, `VoucherLedger`, so status/Paid/Total are recomputed in one place.
- **Numbering:** existing `SequenceRepository` with keys `fee-voucher` and `fee-receipt` → `{CampusCode}-F-{000001}` / `{CampusCode}-R-{000001}`.
- **UI:** a Fees menu group with Fee setup, Challans, Collect fee, Fee reports pages, a challan print page, a receipt print, and a student Fees tab.

**Tech Stack:** .NET 10, ASP.NET Core, EF Core 10 (SQL Server), React 19, TypeScript, Tailwind v4, lucide-react, Python 3 e2e scripts (stdlib).

**Spec:** `docs/superpowers/specs/2026-11-12-fees-design.md`

## Review Focus

1. **Late fine counted twice:** a payment after the due date adds the fine; when the remaining balance carries forward, the fine must not be added again (and a carried voucher that never got a payment adds it exactly once). Test: Task 5 `fine_once_across_payment_and_carry`.
2. **Cancelling the newest challan:** the carried-forward voucher returns to its exact previous status (PartiallyPaid stays PartiallyPaid) with its balance intact, and regenerating the month carries it again with the same arrears. Test: Task 4 `cancel_restores_partial_status`.
3. **Fee structure or concession changed after challans are issued:** issued challans keep their lines and totals; only new challans use the new amounts. Test: Task 3 `voucher_snapshot_survives_structure_change`.
4. **Generate clicked twice at once:** each student still ends with exactly one challan for the month (unique filtered index + catch on save → skipped). Test: Task 3 `double_generate_one_voucher`.
5. **Student leaves with a balance:** no new challan is generated, but the open balance stays on the defaulters list flagged Left and can still be collected. Test: Task 6 `left_student_still_defaulter`.
